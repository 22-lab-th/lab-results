# Frozen protocol

Freeze tasks and this protocol before inference. 36 original BFCL-style tasks, not actual BFCL or vendor tasks: 10 single, 8 tool selection, 10 parallel, 8 no-call; 5 Thai tasks (2 single, 1 selection, 1 parallel, 1 no-call).

Three full repetitions per model, even at greedy temperature 0, to expose nondeterminism. Model order Saluki then Qwen3.6 Q5. No downloads planned: different-base comparison explicitly authorized by owner. This answers a practical pairwise question, not quantization causality or replication of the vendor's same-base claim.

One owned server at a time on an available port >=8090. Existing server on 18080 is left alone. Context 8192, single slot, Metal offload 99 layers, flash attention on, no prompt cache, seed 42, max output 512, temperature 0, top_k 1, thinking off. Both models use the exact Saluki embedded Jinja template saved at chat-template.jinja, frozen by SHA256. Tools use auto selection and parallel calls enabled. No extra response_format or explicit grammar. Runtime may supply automatic tool grammar/parsing; record logs and treat format score as API-interface score rather than raw unconstrained token syntax. No actual tools executed, no tool replies/multi-turn agents.

Exact full-call-set score: function name and all JSON arguments equal expected, extra/missing calls fail; object key order and call order ignored, array order preserved, JSON numbers compared by value, strings exact. No-call passes if no tool calls and no leaked tool syntax, with nonempty natural-language content. Missing required inputs must trigger clarification, not invented arguments. Content quality of no-call answers is not graded. Format slip: malformed call JSON, schema-invalid arguments/unknown tool, leaked tool markup in content, or truncated response. A semantically wrong but schema-valid call is an accuracy error, not a format slip. A missing parallel call alone is also an accuracy error. Report overall and parallel-only format denominators explicitly.

Speed: aggregate server timings prompt_n/prompt_ms and predicted_n/predicted_ms, plus per-task median generation tok/s; exclude warmup and loading from timing. Include all scored responses. Tokens/s is not response latency or general long-output speed. Peak RAM: /usr/bin/time -l maximum RSS and peak memory footprint, plus sampled process RSS; Apple Metal unified memory may not all be reflected in RSS. Not whole-system peak RAM. File GB is decimal; RAM GiB is binary. Pass criteria: Saluki accuracy no more than 5 percentage points below comparator; format slips <=20% (overall AND parallel subgroup); aggregate generation >20 tok/s. Small sample provides no equivalence proof. Three repeats are correlated, not 108 independent tasks. No paid APIs; spend $0.

## Round 2 — frozen hard suite

Round 1 above is unchanged. Freeze tasks-hard.json and system-hard.txt with freeze-hard.json before any round-2 inference. Forty tasks: eight each selection, nested, parallel, dependent, clarification; ten Thai prompts with Thai argument values. Each request has the same 24 tools, deterministically rotated to vary placement, including close-name distractors. A longer policy prompt establishes distinctions, missing-field behavior and literal preservation. This is an original synthetic test, not BFCL.

Rationale: selection tests confuse adjacent operations (void/refund, shipment/order, draft/send), corrections and distractors. Nested tasks stress address objects, ordered line arrays, enum service and leading-zero postal codes. Parallel tasks require three or four calls with different arguments, status enums and ordered Thai/English tags. Dependent tasks require an initial lookup, selection using status AND city, and a second call using a returned opaque ID; three returned records and an untrusted memo distract from the target. Clarification cases omit nested/required fields or contain explicitly unresolved conflicting statuses; empty placeholders and invented defaults fail.

All three models run three times at temperature 0, seed 42, thinking off, original 8192 context and 512 output cap, single slot and the exact original shared template path. One owned server at a time; unrelated servers untouched. Model order Saluki, Qwen3.8 Q8, Qwen3.6 Q5. One task pass requires every stage exact; dependent stage 2 is issued after appending the actual model stage-1 assistant message and a simulated tool reply. Only the expected lookup receives the fixture; wrong calls receive a lookup error. No tool is executed. Independent call order is ignored but array order is preserved.

Clarifications additionally require nonempty content mentioning the missing field/conflict through frozen English/Thai regexes and question/request language. This deterministic proxy does not fully evaluate meaning and can reject valid paraphrases. Denominator: 40 tasks/run, 120 task repetitions/model, 144 stage responses/model. Any stage format error fails task format; parallel subgroup uses 24 task repetitions/model. Throughput sums every scored stage, excludes warmup and follows llama.cpp duration-weighted decode timings; RSS includes loading via time -l and separately samples after readiness. Original pass thresholds apply: Saluki within 5 percentage points of same-base comparator, format slips <=20% overall and parallel, generation >20 tok/s. No threshold or task changes after results. A ceiling, if still observed, must be reported, never repaired by post-hoc task selection.
